## ─────────────────────────────────────────────
## 1. PROJECT CONTEXT
## ─────────────────────────────────────────────

You are building the frontend for FORGE — an AI-powered game prototype
generator. The UI is a 6-step wizard where each step generates content
via AI, shows it for human review, and only saves to the database when
the user approves.

The backend runs at http://localhost:8000
This frontend runs at http://localhost:3000

Design philosophy:
- Dark theme, professional, game-dev aesthetic
- Clean and organized — like a Figma workspace
- Each step feels like a document/canvas being filled in
- Clear visual distinction between AI-generated and approved content
- Progress is always visible

## ─────────────────────────────────────────────
## 2. TECH STACK
## ─────────────────────────────────────────────

- Next.js 14 (App Router)
- Tailwind CSS
- shadcn/ui components
- No authentication — single user experience for now
- No state management library — use React useState/useReducer + Context

## 4. TYPESCRIPT TYPES (lib/types.ts)
## ─────────────────────────────────────────────

Define these types:

type WizardStep = 1 | 2 | 3 | 4 | 5 | 6

type StepStatus =
  | 'locked'       // not available yet
  | 'active'       // available to work on
  | 'generating'   // AI is processing
  | 'review'       // ready for human review
  | 'approved'     // completed and approved
  | 'invalidated'  // parent step was modified

type GDDMechanic = {
  name: string
  description: string
  type: 'core' | 'secondary' | 'progression'
}

type GDDLevel = {
  name: string
  description: string
  order: number
  difficulty: 'easy' | 'medium' | 'hard' | 'boss'
  environment: string
  background_prompt: string
}

type GDDCharacter = {
  name: string
  role: 'hero' | 'enemy' | 'npc' | 'boss'
  description: string
  abilities: string[]
  sprite_prompt: string
}

type GDD = {
  project: {
    name: string
    description: string
    genre: string
    elevator_pitch: string
    core_loop: string
    tone: string
  }
  mechanics: GDDMechanic[]
  levels: GDDLevel[]
  characters: GDDCharacter[]
  art_direction: {
    style: string
    palette: string
    resolution: string
    references: string[]
  }
  audio_direction: {
    music_mood: string
    music_style: string
    sfx_notes: string
  }
  development: {
    estimated_scope: string
    core_features: string[]
    out_of_scope: string[]
    suggested_engine: string
  }
}

type SpritePreview = {
  character_name: string
  character_role: string
  sprite_prompt: string
  preview_url: string
  placeholder: boolean
  approved?: boolean
}

type Project = {
  id: string
  name: string
  description: string
  genre: string
  target_engine: string
  status: string
  concept: GDD
  created_at: string
  current_step?: WizardStep
  current_wizard_step?: Record<WizardStep, StepStatus>
}

type Asset = {
  id: string
  project_id: string
  name: string
  type: string
  discipline: string
  review_status: 'pending' | 'approved' | 'rejected' | 'invalidated'
  current_version?: {
    storage_url: string
    metadata: Record<string, any>
    prompt_used: string
    model_used: string
  }
}

Implement these functions:

// Health

## 7. NEW PROJECT PAGE — STEP 1 (app/new/page.tsx)
## ─────────────────────────────────────────────

This is where the wizard begins.

Layout — three states:

STATE A: Input
  - Full screen dark layout
  - Center: large text "Con qué idea de juego nos divertiremos esta vez?"
  - Large textarea (min 3 rows) — placeholder: "Describe tu juego..."
  - Character counter below textarea (10-1000 chars)
  - Button: "Generar GDD" (disabled if < 10 chars)

STATE B: Generating
  - Show GeneratingOverlay component:
    - Animated spinner or pulsing logo
    - Text: "Gemini está diseñando tu juego..."
    - Subtle progress animation (not a real progress bar — just visual)
    - DO NOT show the textarea anymore

STATE C: Review (GDD received)
  - Show WizardProgress at top (Step 1 active)
  - Show GDDCanvas component with full GDD
  - Show ApprovalBar at bottom:
      Left: "Regenerar" button (goes back to STATE A with same prompt)
      Center: GDD summary (name + genre)
      Right: "Aprobar y continuar →" button
  - Approving calls approveStep1() → then navigates to /projects/{id}

## 9. WIZARD PROGRESS COMPONENT (components/layout/WizardProgress.tsx)
## ─────────────────────────────────────────────

Shows the 6 steps at the top of every project page.

Visual design:
  Step 1 ──── Step 2 ──── Step 3 ──── Step 4 ──── Step 5 ──── Step 6
  [✓ GDD]  [✓ Sprites]  [● Levels]  [🔒 Code]  [🔒 Audio]  [🔒 Export]

Each step node:
  ✓  approved   → green circle with checkmark
  ●  active     → purple/white circle, current step
  ⚡ generating → pulsing animated circle
  ⚠️  invalidated → amber circle with warning icon
  🔒 locked     → gray circle with lock icon

Clicking an approved step navigates back to it (with invalidation warning if needed).
Clicking a locked step shows a tooltip "Complete previous steps first".

Props:
  steps: Array<{ step: number, label: string, status: StepStatus }>
  current_step: number
  project_id: string

## 10. PROJECT PAGE (app/projects/[id]/page.tsx)
## ─────────────────────────────────────────────

Loads the project and determines which step to show based on current_step.

Flow:
1. Fetch project from GET /api/projects/:id
2. Determine current step from current_wizard_step
3. Render WizardProgress at top
4. Render the correct Step component based on current step:
   step 1 approved → show Step2Sprites
   step 2 approved → show Step3Levels
   etc.

Each Step component (Step2 through Step6) has three states:
  - IDLE: "Ready to generate. Click to start."
          Button: "Generar [step name]"
  - GENERATING: Loading overlay (same as Step 1)
  - REVIEW: Show generated content + ApprovalBar

## 18. INVALIDATION FLOW
## ─────────────────────────────────────────────

When user clicks on an already-approved step in WizardProgress:

1. Show a confirmation modal:
   "¿Regresar al Paso {N}?"
   "Los pasos {N+1} hasta {current} serán marcados como inválidos
    y deberás regenerarlos. El contenido anterior se conserva como historial."
   Buttons: "Cancelar" | "Sí, regresar"

2. If confirmed:
   - Call PATCH /api/projects/:id/invalidate-from-step with from_step: N+1
   - Update local step statuses to 'invalidated'
   - Navigate to that step
   - The step shows its previous approved content with an amber banner:
     "⚠️ Este paso fue modificado. Regenera para actualizar el contenido."

## 20. DESIGN SYSTEM — COLORS AND STYLE
## ─────────────────────────────────────────────

Use Tailwind with this dark theme consistently:

Background levels:
  bg-[#0a0a0f]   ← page background (darkest)
  bg-[#0d0f16]   ← card background
  bg-[#13151f]   ← elevated surface
  bg-[#1a1e2e]   ← hover state

Text:
  text-white           ← primary titles
  text-slate-300       ← body text
  text-slate-500       ← muted / secondary

Accent (primary actions):
  bg-violet-600        ← primary buttons
  hover:bg-violet-500
  text-violet-400      ← links and accents

Status colors:
  approved   → green-500 / green border
  pending    → yellow-500 / yellow border
  rejected   → red-500 / red border
  locked     → slate-600 / slate border
  invalidated → amber-500 / amber border
  generating → violet-500 / animated pulse

Borders: border-slate-700 / border-slate-800

Font: default Next.js (Geist) — no custom fonts needed

Cards: rounded-xl, border border-slate-800, bg-[#0d0f16], p-4
